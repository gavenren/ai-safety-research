This plan adopts design-gates-order.md, design-cancel-receipt.md, and design-pagination.md, with these pre-execution details and overrides. No scored test has run. ## Question and contribution

Do the five declared local rules expose or prevent the selected failure patterns when their commands and reads use real saved records in Google Drive and Google Calendar? This is a small controlled extension of the five existing finite studies. The algorithms are not claimed to be new. Current provider sources were checked by design agents; the design files give their search terms, dates, URLs, and reading scope. Existing original reports and references remain applicable to prior research. A limited search does not establish novelty.

## Assigned cases and controls

- Gates: eight cases, four policies by schedules G1 and G2. Forty scored boundaries. Two shared Drive folders reset and checked between cases. Real browser reads follow allowed decisions; audit reads have a separate role.
- Order: six Calendar cases, fixed/greedy/complete under the supplied witness and all-valid control. Three bits are title, location, description. Priority bac.
- Cancellation: eight cases, C1 through C4 on both providers. Deliberate check/cancel/send ordering tests the client check-use gap; native atomic fencing is unavailable and untested.
- Receipts: twelve cases, key-only/bound by exact/payload/target pairs on both providers. First operations are browser saves; second requests are online local receipt decisions. Each case has fresh A and, for changed-target, B records.
- Pagination: one real provider chain per site, four known fixtures each, maximum one result per page, maximum eight pages. Fixed policies are replayed locally on these saved traces; these replays are not additional website trials. Eight fixed exact-ID local filters across the two traces. Empty-query control per site. Nonfinal empty or short pages and incompleteSearch=true are untested unless they occur.

Do not pool synthetic cases, live browser cases, page traces, or local replay cases. No random sampling, probability estimates, or independence claims are justified. These selected witnesses and controls are an engineering check.

## Setup contract and allowed actions

Root owns account mutations. Connectors may create fixtures and read full saved resources. This overrides design text that requires browser fixture creation. Scored field changes and guarded reader checks use the supported browser. Setup is not a scored browser trial. Connector setup avoids unnecessary UI work and supplies native IDs. No permissions are changed.

Calendar events are private, free, nonrecurring, all-day on 2026-10-01, exclusive end 2026-10-02. No guests, conference, or reminders. Order fixtures use TEST-A1 title suffix, TEST-B1 location, TEST-C1 description. Cancellation and receipt fixtures use description tokens BASE/OLD/NEW/PAYLOAD-A/PAYLOAD-B and empty location. Prefix is kept in each title. Description normalization permits only trailing CR/LF removal; no other whitespace or HTML normalization is allowed. Unexpected markup makes the check unknown.

Drive fixtures are empty folders in a new run-owned container. Page fixtures have a separate parent. Names retain the namespace and object alias. Folder metadata checks ID, name, folder type, parent, and trashed state. Do not infer identity from names alone.

One unscored UI readiness case per provider may be used before scored work. Store it separately and preserve any issue. Freeze a change before dependent scored cases if observed UI needs a protocol change.

## Measures and decisions

Compare actual stored fields with expected fields. Retain complete response bodies privately and public alias-only evidence. Log each local decision before its dependent browser action. Store before/after observations and UTC time. A Save toast is action evidence only. Reopen or reload and independently read the resource through its connector before the next dependent trial action. A missing field or uncertain identity is UNKNOWN. No blind repeated writes, no replacing failed cases, no post-outcome repair inside a scored path.

Gates: unsafe permitted read with any PENDING fixture; unnecessary refusal with both DONE; final work state and final gate state separately. Order: target reached and every saved state valid separately. Cancellation: local check/cancel/send order and actual OLD/NEW effect separately. Receipts: protocol decision, second mutation count, and actual intended-field agreement. Pagination: returned aliases, actual token links, final-token status, manifest equality, and explicit coverage evidence; absent coverage remains unknown.

## Bounds, privacy, and cleanup

No external messages or invitations. Stop on unrelated data, unknown identity, unexpected collateral change, or permission prompt. Keep unresolved assigned cases.

Only synthetic fields and aliases are public. Raw IDs, account information, URLs, opaque tokens, full UI observations stay under private/. Public traces contain token hashes, not tokens.
