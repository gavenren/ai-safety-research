# Repeat the field-snapshot study

Read [report.md](report.md) for the question, result, and limits. This is a synthetic count and proof study. It makes no account or browser calls. The [plan](analysis_plan.md) was frozen before calculation. No randomness, model inference, network access, or external data is needed to repeat the calculation.

## Environment

The recorded run used Python 3.14.7 on macOS. Only the Python standard library is required. No dependency installation is needed. See [environment.json](environment.json). The exact immutable Codex model build is unavailable. Model outputs are not experimental observations.

## Procedure

Download this folder at one fixed Git commit. Keep all files together. From this folder, run:

```sh
python3 -m unittest tests -v
python3 analyze.py --input-dir . --output-dir .
python3 independent_audit.py --config config.json --output-dir .
python3 independent_compare.py --input-dir . --output independent_comparison.json
```

All commands must exit with status zero. The calculation must give 18 settings, 108 policy rows, 13,744 terminal count rows, and 71 witnesses. The largest setting contains 1,102,867,934,792 histories. This number is a count represented by the calculation, not a number of live trials.

For a clean reproduction, copy the four scripts and all four frozen input files (`analysis_plan.md`, `config.json`, `source_search.md`, and `input_manifest.json`) to a new folder and run the same commands. Compare all five generated main result files and five independent result files listed below byte for byte. Also check that the four frozen input files are unchanged. Logs contain execution details and can differ. The comparison receipt contains hashes of its inputs. Do not edit the frozen plan to make a failed check pass. Record any change as a separate analysis.

## Data schema

In `results.csv`, `fields`, `passes`, and `writes_per_gap` define a setting. `policy` selects a rule. `total_histories` is the size of its fixed history set. `accepted`, `no_common_target`, `wrong_at_decision`, and `rejected_correct_final` are counts. The two `min_*_writes` fields are blank when their outcome set is empty. See the CSV header for exact column names.

Terminal rows contain the current vector, total and covered-field write counts, whether the target ever existed, whether all reads matched, and the number of histories. Field zero is the first displayed bit. Each group in `stage_totals.json` gives the gap position; terminal rows are after the final gap. A witness includes every intermediate write state so that a briefly correct target is not missed. Lexical ties use the initial bit tuple, then the tuple of gap words.

The independent terminal file uses a different representation. Use `independent_compare.py` to align the two schemas. Do not compare those two files as raw text.

## Scope and rights

Counts cover all histories in the declared finite sets. They are not natural failure probabilities. No statistical sampling uncertainty is present; real-system applicability remains uncertain. The full-revision guarantee requires a fresh, complete, atomic, non-reused revision and no later write before the decision. The ideal final snapshot is a stronger comparison interface.

The package contains synthetic data and new study text. Third-party papers are not copied into it. No new license is assigned. Source rights remain with their owners. Codex generated the package; separate agent checks are recorded. There was no human review or peer review.
