# Independent review of the production extension

Status: PASS_WITH_LIMITATIONS. The evidence supports publication of the reported bounded results. This status does not mean that the experimental hypotheses or all procedure checks passed.

A separate Codex context performed this review. It did not design the plan, run the website trials, or write the main analyzer. This is an AI review. No human or external peer review is claimed.

## Method

The reviewer read the frozen plan and assignments first. It then wrote `production_independent_replay.py`. That script does not import the main analyzer or use its result files to set outcomes. It parses saved UI states, action times, native Notion page links, and Calendar connector responses. It checks complete controls, exact query and date coverage, the first creation request, one-repeat bounds, the 24-second reload, decisions, audit identities, and cleanup. Missing identity agreement and unknown task fields stay unknown.

The review also compares private originals with public evidence. It checks record order, original hashes, retained time and decision fields, stable identity aliases, and independent count parses. It scans new public text for private account strings, original record identities, local paths, encoded event identities, and secret patterns. The image archive must contain exact original task crops. Original private data remains local.

- N01 decision and audit image files have identical original bytes with repeated partial regions. They cannot establish a visual count. Complete saved text and native links support the outcome. Its first cleanup image still shows one row; the later final cleanup image shows zero.

## Corrections from this review

The first public Calendar extraction omitted a progressbar inside a removed sidebar. The corrected extraction preserves an explicit marker for removed loading state. This prevents a public replay from treating the original unknown state as ready.

The initial main analyzer used every cleanup-phase action as the audit cutoff. A read-only menu in N01 preceded its valid native-ID audit. The corrected cutoff is the first effective Trash or delete request. Native IDs used for the audit come from after the decision and before that request. A conflict between visible row count and distinct identity count now remains unknown. These are analysis corrections, not new website trials.

## Scope of support

The fixed tasks, selected accounts, shared browser, small cell sizes, supplied rules, and visible writer feedback limit the result. Counts do not estimate natural production failure rates. Calendar audits use the exact token and January 2000 date bounds. They cannot exclude records with another title or a date outside that range. The saved pre-Save forms show the intended fields. The Notion audit covers all rows in the new test database. No unintended partial record was observed within these audit scopes. A later audit does not prove indefinite durability or execution closure. Procedure departures and failed All controls prevent a filter-only causal claim.

The four new provider references were opened and read for the stated features. Notion documents view-specific filters and recoverable Trash. Google documents Calendar search and Trash. Google also states that a first Trash deletion can cause a service email. The study must not claim that no service email occurred. Relevant NeurIPS checklist items were used as a review aid for claims, limitations, reproducibility, rights, and ethical issues. This is not conference approval.
