# Live field-check instructions

Read the final field_plan.md, field_assignments.csv, fieldcheck.py, and field_contract.md before scored work. Verify their hashes in field_plan_manifest.json. Do not begin from draft files. Preserve every assignment and error. Use the assigned order for your service.

## Procedure

1. Set the exact assignment and new unique token. Reload the complete test database or bounded October 2026 Calendar query. Verify that no active test record is present. Save the ready observation and the query/view controls. Loading, missing tables, and hidden views are not zero.
2. Reserve one Create before the effective New or Save call. Record the operation key, time, and pending state. Never reset it. Create the assigned initial values once. The deliberate field change is part of initial entry, not a repair. Capture the first native identity from the visible page link or event edit URL.
3. Complete the initial entry. Close any property editor. Read the native page and then reload it. Require the native title/header, complete required controls, and no loading or pending editor. A nonmodal Writing Replay prompt may remain only if it does not obscure the title or properties. Save that fact. Do not change extension settings.
4. Read every requested saved field. Calendar must save a read-only visible DOM read of the Description textbox. It must also make the bounded full query and detailed event read. Do not use API writes. Notion must save Marker and Verified property rows, title, empty body, and the unfiltered parent table. Record initial field statuses and references before any repair. A wrong field must be observed after saving, not inferred from the requested injection.
5. If the initial verdict is MISMATCH and the first identity is known, admit at most one repair to the assigned wrong field on that same identity. Set the full expected value. For wrong_date, set the start and inclusive end date pair. Do not modify other fields. For correct controls, make no repair. For UNKNOWN, make further reads or stop unresolved. A tool error is not proof that its mutation failed. Do not repeat the mutation after an error.
6. After the repair or control check, close any editor and reload. Read the same native identity, all fields, and a complete covering set again. Record a separate final field check. Full completion requires all MATCH, exactly one record, same identity, no pending edit, and a decision within 300 seconds of initial Create admission. Otherwise report UNRESOLVED. Do not convert a late claim into a timely claim.
7. After the saved final decision, make a separate audit read. Save the covered set and native fields again. Calendar must use a new bounded query and detailed read. Audit results cannot revise the earlier decision. Save an image at initial evidence, final evidence, and audit if useful. Image labels are not evidence of their contents.
8. Move only this trial's record to recoverable Trash. Verify zero active records. If a row remains, inspect its native identity and state before another cleanup action. Do not empty Trash. After all Notion trials, verify the parent is empty, trash the parent, and verify its same-ID restore page. Calendar ends with a bounded prefix query that finds zero active test records.

## Packet schema

Keep actions.jsonl as the original full private log. Keep raw connector replies in files. Write one packet JSON file per trial after cleanup. The main analysis will derive values from the referenced raw evidence; it will not trust the packet's success labels.

Each packet has trial_id, service, token, condition, first_native_id, create_admission_ids, create_action_ids, repair_admission_ids, repair_action_ids, final_decision_record_id, cleanup_record_ids, and checkpoints.

checkpoints has initial, final, and audit objects. Each checkpoint contains native_state_id, native_value_read_id (if the native value is absent from the snapshot), covered_state_id, covered_identity_record_ids, connector_files (Calendar), field_check_record_id, and native_id. Use null plus a reason when evidence is absent. Never substitute a later state for a missing earlier state. One state may support several checks only when its actual contents support them.

Each field_check record gives raw observed values, per-field statuses, overall MATCH/MISMATCH/UNKNOWN, the observation source IDs, and the time. The final decision record gives CONFIRM or UNRESOLVED, elapsed seconds, and the exact supporting field-check ID. Save mutations before calls and action errors after calls. Use explicit keys rather than compressed alternate forms.

## Reports and privacy

When all trials end, save run_summary.md/json, immutable hashes of each original file, and exact cleanup evidence IDs. Save original private evidence locally. Do not publish raw names, emails, IDs, or unrelated account contents. Do not crop or edit images with external tools. A separate review will decide which original images are safe to publish. Keep all failed or misleading captures with their real status.
